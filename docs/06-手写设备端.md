# B1：虚拟音响 —— 手写设备端（收官课）

> 前五课我们写了"控制点"（发号施令的一方）。这一课反过来：
> 用 Python 手写一台**极简 DLNA 音响（MediaRenderer 设备端）**，
> 让你手机上的 App 去发现它、控制它、订阅它的事件 ——
> 协议两端都出自我们之手，UPnP 才算真正闭环。

## 运行方式（在与你手机同一 Wi-Fi 的电脑上）

```bash
python virtual_speaker.py
```

- 只需 Python 3.8+，**零第三方依赖**（纯标准库）
- 首次运行 Windows 弹防火墙：勾选"专用网络"允许（否则手机连不上）
- 脚本启动后控制台会打印：本机 IP、HTTP 端口、UUID、当前状态
- 按 `Ctrl+C` 退出，退出前会广播 `ssdp:byebye` 通知控制点

## 它会"扮演"什么

```
  设备描述:  urn:schemas-upnp-org:device:MediaRenderer:1（DLNA 音响）
  服务1:     AVTransport          —— SetAVTransportURI / Play / Pause / Stop / GetTransportInfo
  服务2:     RenderingControl     —— SetVolume / GetVolume / SetMute / GetMute
  HTTP:      端口 8200（描述 / SCPD / SOAP / GENA 全在这一个端口）
  SSDP:      加入 239.255.255.250:1900，应答 M-SEARCH，广播 alive/byebye
```

## 与 App 的互测步骤

1. 电脑跑 `virtual_speaker.py`，手机连同一 Wi-Fi
2. 手机 App → 开始扫描 → **"其他设备"分组**里会出现 `虚拟音响(MyUPNP B1)`
3. 点它 → 「播放器场景」→ 填任意 URL（如电脑上别的 mp3 地址）→ 推送播放
   - 脚本控制台会打印 `SetAVTransportURI` → `Play` → 状态 STOPPED→PLAYING
4. 点「暂停/停止」→ 控制台状态跟着变
5. 点「订阅状态」→ App 发 SUBSCRIBE，脚本回 SID；
   之后在 App 里点音量 + / -，脚本推 NOTIFY，App 日志能看到
   `Volume = xx` / `TransportState = PLAYING` —— 完整事件闭环
6. 关掉脚本（Ctrl+C）→ App 心跳清理会在 ~45s 后移除该设备

## 站在"设备侧"重看一遍协议（本课要点）

| 之前控制点做 | 现在设备端做 | 代码 |
|---|---|---|
| 发 M-SEARCH | 监听 1900 并**单播**回 200 OK + LOCATION | `ssdp_loop` |
| 收 NOTIFY alive | 启动时广播 3 次 NOTIFY alive | `send_notify_alive` |
| GET description | 提供 `/rootDesc.xml`（deviceType + serviceList） | `DESC_XML` |
| GET SCPD | 提供 `/scpd/*.xml`（声明支持的动作+参数） | `scpd_xml` |
| POST SOAP 动作 | 按 SOAPACTION 分发执行，回 200 信封 / 500 Fault | `do_POST` |
| SUBSCRIBE | 发 SID，保存 callback | `do_SUBSCRIBE` |
| 收 NOTIFY propchange | 状态变化 → 主动往 callback 推 LastChange | `push_event` |

**几个设备侧的坑（控制点永远不会遇到，这里全踩过）：**
- M-SEARCH 应答必须**单播**回控制点地址，不能组播（否则控制点收不到）
- USN 后缀随 ST 变化（rootdevice / 设备类型 / 服务类型各一个 USN）
- SUBSCRIBE 的 CALLBACK 用 `<>` 包住；回包必须带 SID
- LastChange 是**再转义一层**的 XML（`&lt;Event...&gt;`），控制点要先反转义
- 上线要主动广播 alive（否则早就在扫的控制点发现不了你）；退出要广播 byebye

## 代码结构（单文件 300 余行）

```
virtual_speaker.py
  Renderer          设备状态机 + LastChange 事件推送 + GENA 订阅管理
  ssdp_loop         组播监听 + M-SEARCH 应答（设备侧被动）
  send_notify_alive / byebye   主动广播上下线
  HttpHandler       GET(描述/SCPD) + POST(SOAP) + SUBSCRIBE/UNSUBSCRIBE(GENA)
  DESC_XML / scpd_xml() / soap_response() / soap_fault()
```

- ✅ `python -m py_compile` 语法通过

- ✅ `/scpd/AVTransport.xml` 返回动作清单
- ✅ SOAP SetAVTransportURI / Play → HTTP 200 + SOAP 信封
