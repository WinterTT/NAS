# 08 - 换电脑继续开发（环境与构建）

> 目标：换一台电脑后，能在 **15 分钟内**把工程跑起来、继续开发与真机验证。
> 本文记录**与机器相关的信息**（SDK/JDK/缓存/推送状态），代码本身不依赖某台机器。

---

## 1. 代码怎么搬（两种方式，任选）

### 方式 A：Git（推荐）

```powershell
# 老电脑：先把本地提交推上去（重要！本地可能领先远端）
git push origin main

# 新电脑
git clone https://github.com/WinterTT/NAS.git  MyUPNP
cd MyUPNP
git checkout main
```

远端：`https://github.com/WinterTT/NAS.git`（分支 `main`）

**注意**：老电脑上如果有**未推送的提交**，只 clone 是拿不到的——先 push，或走方式 B。

### 方式 B：整目录拷贝（网络不便时）

直接拷 `MyUPNP` 整个目录（含 `.git`，会把未推送提交一并带走）：

```powershell
# 建议排除可再生的构建产物，体积能小很多
robocopy F:\workespace\MyUPNP  D:\workespace\MyUPNP /E ^
  /XD build app\build .gradle .gradle-home .android-home .kotlin .idea
```

拷完把 `.git` 一起带过去即可（仍然可以把 4 个提交 push 到 GitHub 备份）。

## 2. 新电脑要装什么

| 依赖 | 版本/要求 | 说明 |
|---|---|---|
| **JDK** | 17 或 21（老机是 21.0.7 LTS） | Gradle 9.6 需要 JDK 17+；`JAVA_HOME` 指向它 |
| **Android SDK** | platform **37**、build-tools、platform-tools、cmdline-tools | 老机路径：`C:\Users\Administrator\AppData\Local\Android\Sdk` |
| **Gradle** | 不用装 | 用工程的 wrapper（`gradlew.bat`，自动下载 **Gradle 9.6**） |
| **网络** | 能访问 `services.gradle.org` 与 Maven 仓库 | 首次构建要下 Gradle + 依赖 |

### 配置 SDK 路径

新电脑的 SDK 路径要在 **`local.properties`**（该文件被 gitignore，不会从仓库带过来）：

```properties
sdk.dir=C\:\\Users\\<你的用户名>\\AppData\\Local\\Android\\Sdk
```

或者不写文件，直接设环境变量 `ANDROID_HOME` / `ANDROID_SDK_ROOT`。

## 3. 构建命令（本工程一贯用法）

沙箱/无网盘环境下，把 Gradle 缓存与 Android 用户目录放进工程内，避免写系统盘受限：

```powershell
$env:GRADLE_USER_HOME='F:\workespace\MyUPNP\.gradle-home'
$env:ANDROID_USER_HOME='F:\workespace\MyUPNP\.android-home'
.\gradlew.bat --no-daemon :app:assembleDebug
```

- 产物：`app\build\outputs\apk\debug\app-debug.apk`（直接装到手机验证）
- 跑既有单测（回归用）：`.\gradlew.bat --no-daemon :app:testDebugUnitTest`
- 提示：`.gradle-home` / `.android-home` 已被 gitignore；新机可**让它们重新生成**（要下载），
  也可以从老机拷过去但**路径变了可能失效**，拷了不行就删掉重建。

## 4. 真机验证需要什么

- **手机**与 DLNA 设备（音箱/电视/PC MediaServer）在**同一 Wi-Fi**
- 手机装 debug 包：`adb install -r app\build\outputs\apk\debug\app-debug.apk`
- 看日志：`adb logcat -s MyUPNP`
- 首次启动会给"三步使用引导"并申请「附近的设备」权限（Android 13+）

## 5. 数据存放在哪（换机时会"丢"的东西）

工程内**没有任何用户数据**，都是手机 App 本地的（SharedPreferences / SQLite）：

| 数据 | 位置（手机内） | 换机影响 |
|---|---|---|
| 设备快照 / 扫描意图 / 队列 / 历史 / 上次会话 | `app_state`、`device_cache`、`play_queue`、`play_history`、`playback_memory` | 只存在手机上；换电脑无影响 |
| 曲库索引 | `media_index.db`（SQLite） | 换电脑无影响；App 升级改 schema 会重建，需要重新索引 |
| 收藏 / 别名 | `device_meta` | 同上 |

## 6. 如果想在另一台电脑继续用 AI 助手（DSH）

助手环境在 **`C:\Users\<用户名>\.dsh`**（DSH_HOME），它不是工程的一部分：

| 目录/文件 | 内容 |
|---|---|
| `.dsh\sessions\` | 会话历史（含本项目的对话记录） |
| `.dsh\profiles\web\` | Web GUI 的 profile 配置 |
| `.dsh\settings.yaml` | 模型配置（例如已登记的 `deepseek-v4-flash-vision-exp`） |
| `.dsh\credentials*` | 凭据（如果配置过） |
| `.dsh\start-web.cmd` / `stop-web.ps1` | 启动/停止脚本（**内含绝对路径，换机要改**） |

迁过去后，注意把启动脚本里的工程路径与 DSH_HOME 改成新机的路径。
