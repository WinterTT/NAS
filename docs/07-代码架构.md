# MyUPNP 代码架构

本工程从零手写实现了一个 **DLNA/UPnP 控制点 App**（发现 → 描述 → 控制 → 事件 → 播放），
外加一个 Python 虚拟音响设备端（B1）。本文说明各文件职责与依赖，方便后续扩展。

---

## 1. 总览：模块职责划分

```
                     ┌─────────────────────────────┐
                     │  MainActivity（UI 编排层）    │
                     │  按钮/对话框/列表/权限/生命周期│
                     └──────┬──────────┬───────────┘
                            │          │
              ┌─────────────▼──┐   ┌───▼──────────────┐
              │ DeviceRegistry │   │ SubscriptionManager│
              │  设备列表/心跳   │   │  GENA 订阅生命周期  │
              │  描述拉取/分组  │   │                    │
              └──────┬─────────┘   └───┬───────────────┘
                     │                 │
              ┌──────▼─────────────────▼──────────────┐
              │        NowPlayingSession                │
              │     正在播放会话（钉住设备+曲目）         │
              └────────────────────────────────────────┘
                     │  调用（经 SoapCaller / GenaClient）
                     ▼
        ┌────────┬─────────┬──────────┬─────────┐
        │ ssdp/  │ soap/   │ gena/    │ dlna/   │ device/   ← 协议实现（无 UI）
        │ 发现   │ SOAP    │ 事件     │ DLNA    │ 描述/SCPD │
        └────────┴─────────┴──────────┴─────────┘
```

**分层原则**：
- 协议包（`ssdp/ soap/ gena/ dlna/ device/`）只做协议，不依赖 Activity。
- 状态类（`DeviceRegistry / SubscriptionManager / NowPlayingSession`）持有逻辑与状态，
  通过 **Listener 接口**通知 UI，自身不碰 View。
- `MainActivity` 只做**编排**：建对话框、转发用户操作、把状态变化画到界面。
- `model/` 放纯数据模型（无逻辑）。

## 2. 文件地图

### 2.1 协议层（独立、可复用、可单测）

| 文件 | 协议 | 职责 |
|---|---|---|
| `ssdp/SsdpDiscovery.kt` | SSDP | 组播引擎：双 socket（搜索+监听）、M-SEARCH、NOTIFY |
| `ssdp/SsdpMessage.kt` | SSDP | 报文模型与解析（类型 + 首部 map） |
| `device/DeviceDescriptionLoader.kt` | HTTP | 拉取 description.xml 并解析（含 URL 绝对化） |
| `device/ScpdLoader.kt` | HTTP | 拉取 SCPD 动作清单 |
| `soap/SoapCaller.kt` | SOAP | 构造信封、POST、解析 200/Fault |
| `gena/GenaClient.kt` | GENA | SUBSCRIBE / RENEW / UNSUBSCRIBE（裸 socket HTTP） |
| `gena/LocalEventServer.kt` | GENA | App 内嵌 HTTP 回调服务器（收设备 NOTIFY） |
| `gena/EventProperties.kt` | GENA | propertyset 报文解析 |
| `dlna/DlnaPlayer.kt` | DLNA | 播放器编排：pushAndPlay、音量、DIDL 构造 |
| `dlna/ContentDirectoryClient.kt` | DLNA | MediaServer 曲库 Browse + DIDL 解析 |
| `dlna/LastChangeParser.kt` | DLNA | LastChange 嵌套 XML 展开 |

### 2.2 状态/逻辑层（重构后新增，不碰 View）

| 文件 | 职责 | 通知 UI 方式 |
|---|---|---|
| `DeviceRegistry.kt` | 设备增删、心跳保活/超时清理、描述拉取、分组判断（含顶层 `Entry` 数据类） | `Listener.onRegistryChanged` |
| `SubscriptionManager.kt` | GENA 订阅/续订/退订/全部退订、SID 反查、续订定时器 | `Listener.onInfo/onError` |
| `NowPlayingSession.kt` | 正在播放会话：钉住设备+服务+曲目、播放/暂停/停止、用事件纠正状态 | `Listener.onChanged` |

### 2.3 UI 编排层

| 文件 | 职责 |
|---|---|
| `MainActivity.kt` | 生命周期、权限、扫描开关、网络监听（A2）、设备列表/控制条渲染、所有对话框 |
| `DeviceListAdapter.kt` | 设备分组列表适配器（Header + DeviceItem） |
| `model/*.kt` | UpnpDevice / UpnpService / UpnpAction / MediaObject 数据模型 |
| `res/layout/activity_main.xml` | 布局（含底部"正在播放"控制条） |
| `res/drawable/ic_*.xml` | 控制条矢量图标 |

### 2.4 设备端（独立 Python）

| 文件 | 说明 |
|---|---|
| `device/virtual_speaker.py` | 极简 MediaRenderer：SSDP 应答/广播 + 描述 + SOAP + GENA（见 docs/06） |

## 3. 关键设计约定（扩展前必读）

### 3.1 线程模型（全 App 一致）
- **网络 IO 一律不进主线程**：引擎在自有线程；HTTP/SOAP/订阅放
  `controlExecutor`；描述拉取放 `fetchExecutor`。
- **回调回主线程**：后台完成后用 `mainHandler.post { ... }` 再碰 UI/共享状态。
- **网络回调（ConnectivityManager.NetworkCallback）在系统线程**，
  一律 post 到主线程再处理。

### 3.2 状态类的事件回调用例（以 DeviceRegistry 为例）
```kotlin
val registry = DeviceRegistry(mainHandler, fetchExecutor, listener = object : ... {
    override fun onRegistryChanged() { requestRefresh() } // UI 只在这里刷新列表
})
```
扩展新功能时：**别让状态类直接持有 Activity/View**，加 Listener 方法即可。

### 3.3 一条用户操作怎么流动（示例：曲库点歌播放）
```
用户点歌 → MainActivity.playMediaItemFromServer()
   ├─ registry.all() 找播放器设备（读注册表）
   ├─ 多台弹选择框（Activity 负责 Dialog）
   ├─ DlnaPlayer.pushAndPlay(renderer, url)（后台，经 SoapCaller）
   ├─ 成功 → subManager.subscribe(...)（订阅事件）
   └─ 成功 → nowSession.begin(...)（建立播放会话 → 控制条出现）
之后 GENA 事件 → handleIncomingEvent → nowSession.applyEvent(...) → 控制条图标更新
```

### 3.4 日志约定
- 界面不再滚动日志（第 6 课后移除）。
- 排查统一走 logcat：`adb logcat -s MyUPNP`。
- 关键节点已按模块打 tag 前缀：`[SSDP] [DEVICE] [DESC] [CDS] [SOAP] [GENA] [NET] [NOW] [SCAN]`。

## 4. 扩展指南（按功能列）

| 想加什么 | 动哪个文件 | 注意 |
|---|---|---|
| 新的协议解析 | 协议包 + model | 保持纯 Kotlin 便于单测 |
| 新的设备类型分组 | `DeviceRegistry.isMediaServer` / 列表 | 扩展判断即可 |
| 新的播放器能力（Seek/队列） | `dlna/DlnaPlayer` + `NowPlayingSession` | 控制条加按钮 |
| 新的服务操作 UI | `MainActivity` 对话框区 | 遵循"对话框 → doSoapCall"模式 |
| 播放进度条 | `NowPlayingSession` + 控制条 | LastChange 已解析出位置字段 |
| 持久化（记住设备/音量） | 新增 Repository 类 | 别直接塞进 Activity |
| 后台常驻扫描 | 把引擎迁前台服务 | 需先抽 ScanController |
