# AdMob 广告接入

本文说明 HavenCast 的广告是怎么接的、上线前要改哪里、以及商店侧要申报什么。

## 1. 产品原则（先定规矩，再写代码）

- **只在「媒体库」页底部放一条自适应横幅**。播放页、搜索页、服务器分类页、任何对话框里都不放广告。
- **不做插屏，不做开屏广告**。播放控制是本应用的命脉，任何打断都属于自毁。
- **不阻塞主流程**：同意流程与 SDK 初始化全程异步；失败、无广告库存、无网络时，只是不显示广告，其余功能完全不受影响。
- **失败即隐藏**：拉不到广告就把容器收起（`GONE`），绝不留一条空白占位。
- **留好开关**：`AdPolicy` 是"是否显示广告"的唯一入口，将来接内购/激励视频时改这一个地方。

## 2. 代码结构

| 位置 | 职责 |
|---|---|
| `ads/AdsManager.kt` | 同意流程（UMP）→ SDK 初始化 → 创建/销毁自适应横幅、生命周期转发 |
| `ads/AdPolicy.kt` | 是否显示广告（`no_ads_unlocked`，将来由 Billing / 激励视频写入） |
| `res/values/ad_config.xml` | **唯一的改动点**：AdMob 应用 ID 与横幅广告位 ID |
| `activity_main.xml` 的 `adBannerContainer` | 媒体库页底部的横幅容器（初始 `gone`） |
| `MainViewModel.ads` | 广告管理器实例（构造期不发请求，由 Activity 显式初始化） |
| `MainActivity` | `onCreate` 里 `initialize` + `attachBanner`；`onResume/onPause/onDestroy` 转发 |

日志统一用 `HavenCast` 标签、以 `[AD]` 开头，排查时：

```powershell
adb logcat -s HavenCast | Select-String '\[AD\]'
```

典型正常输出：

```
[AD] 状态 -> CONSENT
[AD] 同意状态=1，可请求广告=true      # 1 = NOT_REQUIRED（中国大陆等地区无需征得同意）
[AD] SDK 初始化完成
[AD] 状态 -> LOADING
[AD] 状态 -> READY                    # 广告已就位
```

## 3. 上线前必须做的三件事

1. **换成自己的 ID**（`app/src/main/res/values/ad_config.xml`）：
   - `admob_app_id`：AdMob 后台 → 应用 → 应用设置 → 应用 ID（`ca-app-pub-XXXX~YYYY`）✅ 已填真实值
   - `admob_banner_unit_id`：AdMob 后台 → 广告 → 广告单元 → 新建「横幅」（建议选自适应），得到 `ca-app-pub-XXXX/ZZZZ`
   **真实 App ID + 官方测试广告位**是官方推荐的开发期组合（测试广告位在任何 App ID 下都能出广告，
   且不算无效流量）；**反过来（测试 App ID + 真实广告位）才是违规的**，千万别那么干。
   Release 构建会直接报错拦住测试 ID（`checkAdMobTestIds` 任务），
   避免带着测试 ID 上架（没有收入，且可能被判定为无效流量）。
2. **在 AdMob 后台配置同意消息**（隐私与消息 → GDPR）：不配置的话 UMP 会返回
   `Publisher misconfiguration: ... no form(s) configured for the input app ID`，
   欧洲经济区/英国用户拿不到同意表单。代码已把这个失败降级处理（日志警告 + 继续按
   `canRequestAds()` 判断），所以功能不受影响，但**面向 EEA 发布前必须配置**。
3. **Play Console 的 Data safety 如实申报**：广告 ID、设备标识符用于「广告或营销」；
   与隐私政策（`docs/10-隐私政策.md`）里的表述保持一致。
4. **在真实网络下回归**：确认横幅出现、切到播放页没有任何广告、断网时不留空白。

## 4. 合规说明

- **同意流程**：`AdsManager` 使用 Google UMP。在 EEA/英国等地区会弹同意表单；
  中国大陆等地区返回「无需征得同意」，用户不会多看到一个弹窗。
  验证表单本身需要按官方文档用 `ConsentDebugSettings` 指定调试地区 + 测试设备，
  **不要把调试地区写进正式代码**。
- **广告标识符权限**：清单里已显式声明 `com.google.android.gms.permission.AD_ID`
  （Android 13+ 需要它才能拿到广告 ID）。
- **不要点自己的广告**：测试用官方测试 ID；换真实 ID 后，自测时只验证"是否展示"，
  不要点击。违规点击会导致 AdMob 账号被封。

## 5. 需要留意的坑

- **国内应用商店渠道基本收不到 AdMob 的钱**：AdMob 依赖 Google Play 服务，
  而 OPPO / VIVO / 小米（国内机型）等渠道分发的设备通常没有 GMS，**不会出广告（测试广告也不出）**。
  如果主战场是国内商店，需要按渠道另接国内广告平台（穿山甲/优量汇），或国内渠道走"无广告 + 内购"。
  三星商店的海外机型有 GMS，情况好一些。
  当前 AdMob 后台的「App store details」填的是 OPPO/三星/VIVO/小米 GetApps；将来上 Google Play 时补上即可。
- **新账号/新应用有审核期**：AdMob 后台 Approval status 显示 `Getting ready` 时广告投放可能受限，
  要等 Google 审核通过（通常几小时到一两天）。新账号初期填充率也偏低，属于正常现象。
- **国内商店上架另有合规要求**：一般要求在隐私政策里列出「第三方 SDK 目录」
  （SDK 名称、提供方、用途、收集的个人信息类型、隐私政策链接）。接 AdMob 后至少要申报
  Google Mobile Ads SDK 与 UMP，可在 `docs/10-隐私政策.md` 里补一张表。
- **Release 的 R8 压缩**：当前 release 开启了代码优化。AdMob 自带 consumer rules，通常无需额外 keep；
  但发布前必须在 release 包上实测一次广告能否加载（debug 包正常不代表 release 包正常）。
- **`getCurrentOrientationAnchoredAdaptiveBannerAdSize` 已被标记 deprecated**：
  Google 在推 inline adaptive banner。该 API 在 25.4.0 上实测仍能正常出广告，
  等 Google 正式停止服务时改为 `getCurrentOrientationInlineAdaptiveBannerAdSize` 即可（改动只有一行）。
- **无 GMS 的设备**：AdMob 依赖 Google Play 服务。国内无 GMS 的机型不会出广告，
  也不应因此报错——`AdsManager` 的所有失败路径都只是"不显示"。
- **体量**：接入后 debug APK 从 9.8 MB 涨到 13.2 MB（release 经 R8 后增量更小）。
  如果将来同时接国内广告平台，建议评估按渠道分包。
